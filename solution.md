# Solution

## App name & tagline
- **Name:** TaskTie
- **Tagline:** Every task, tied to a vendor.

## Solution statement
> TaskTie helps solo wedding planners make sure every wedding-day task has exactly one owner and a time slot. Planners send vendors a checklist, and TaskTie flags gaps and overlaps and builds the day-of timeline automatically. Today that work lives in email threads, memory, and spreadsheets, where tasks slip through and changes have to be made by hand.

**Who it's for:** Built for wedding planners, but it works for any event with vendors. Both survey respondents planned non-wedding events and described the same problem.

## Core features
| Feature | Pain point it solves (from problem.md) | User benefit |
|---|---|---|
| Standard task library + suggested unique tasks | Lists built from memory miss tasks unique to each wedding | Start every wedding with a complete list, not a blank page |
| Vendor checklists | Back-and-forth emailing with every vendor | Send one kind, high-level email with a link, and the vendor's answers fill in the list |
| Gap & overlap flags | Tasks nobody claims, or two vendors both claim | See problems before the wedding day, not during it |
| Auto day-of timeline | Timing conflicts (photos vs. license signing) | A timeline with a default length for each task, which the planner can adjust |
| Automatic updates | Changes have to be made by hand everywhere | Change something once and the list and timeline update |
| Contact rhythm *(added after survey)* | Vendor communication runs for weeks: weekly emails, calls, follow-ups | Log emails and calls, see who's due for a weekly check-in, and get reminded to send a follow-up email after every call |
| Checkpoints *(added after survey)* | Gaps found too late | Milestones at 8, 4, 2 and 1 weeks before the wedding show what's done and what's overdue |
| Lessons learned *(added after survey)* | The same misses repeat | Note what was missed after a wedding, and add that task to every future wedding |

## How it works (user journey)
1. The planner creates a wedding and adds its vendors (caterer, venue, DJ, and so on).
2. TaskTie loads the standard task list for each vendor type and suggests unique tasks based on the wedding's details.
3. The planner sends each vendor a checklist link, and the vendor checks off the tasks they will handle.
4. TaskTie flags unclaimed and double-claimed tasks. The planner assigns them, and TaskTie builds the day-of timeline.

## What makes it different
- It's built around **who does what**, not budgets, guest lists, or couple-facing planning.
- It **flags gaps and overlaps** automatically, which a spreadsheet or email thread can't do.
- **Built for weddings, works for any event with vendors:** corporate events, parties, and fundraisers have the same who-does-what problem.

## Business model
- **Pricing (proposed, to test):** Free for your first 3 weddings; then $29/month for unlimited weddings.
- **Revenue streams:** Monthly subscriptions from planners.

## Success metrics
- Fewer back-and-forth messages per vendor before every task is confirmed
- Check-ins and follow-ups sent on time (weekly rhythm)
- Number of unclaimed or double-claimed tasks caught before the wedding day
- Planners still active after 30 days

## Risks & assumptions
- **Assumption:** Vendors will fill out a checklist link instead of replying by email. *Test:* Have the survey planners send one checklist to a real vendor.
- **Assumption (updated after survey):** The 45-minute figure was not confirmed. Both planners described communication spread over weeks (one said about 2 weeks for a big event), not one long email. TaskTie now focuses on the ongoing rhythm, not just one checklist email.
- **Risk:** Default task lengths may be unrealistic. *Reduce:* Planners can edit them, and TaskTie learns from their edits.
