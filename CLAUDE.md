# CLAUDE.md — Module 4 App Project

This folder takes an app idea from a real problem to a marketing-ready pitch.
The files build on each other and should be completed **in order**:

1. `problem.md`  — Define the problem and who has it.
2. `evidence.md` — Prove the problem is real and worth solving.
3. `solution.md` — Describe the app that solves it.
4. `web-page.md` — Landing-page copy that sells the solution.
5. `ad-script.md` — A short video/audio ad script that drives people to the web page.

## Rules for Claude when working in this folder
- Keep every file consistent with `problem.md`. If the problem statement changes, update the downstream files.
- Every claim in `solution.md`, `web-page.md`, and `ad-script.md` should trace back to a pain point in `problem.md` or a finding in `evidence.md`.
- Do not invent statistics. In `evidence.md`, every number needs a source (link, citation, or "own survey, n=__").
- Write for the target user named in `problem.md`: plain language, no jargon unless that audience uses it.
- Keep it short and specific. Prefer concrete examples over general statements.
- Replace every `[bracketed placeholder]` before you call a file done.

## Project snapshot (fill in)
- **App name:** TaskTie
- **Target user:** Solo, independent wedding planners running 10–14 weddings at once (~14 vendors each). Built for weddings, works for any event with vendors.
- **Pricing:** Free for the first 3 weddings, then $29/month
- **Problem in one sentence:** Planners spend ~45 minutes per vendor emailing about who handles what, and tasks still slip through (unclaimed, double-claimed, or timeline conflicts), which causes stress and a bad flow on the wedding day.
- **Solution in one sentence:** TaskTie sends each vendor one checklist, flags tasks that are unclaimed or double-claimed, and builds a day-of timeline that updates automatically when anything changes.
